# Контент-политика ассистента

**Архитектурное решение:** Ассистент не применяет фильтры контента на уровне кода.
Ответственность за контент-политику полностью лежит на LLM и системном промте персонажа.

## Почему

1. **Локальный ассистент** — все данные на вашем ПК, нет внешнего модератора.
2. **LLM уже имеет alignment** — современные модели (Qwen, Llama, Mistral) обучены
   на миллионах правил безопасности. Добавление ещё одного слоя в коде избыточно
   и нарушает предсказуемость.
3. **Код — тонкий транспорт** — код ассистента не должен дублировать или усиливать
   политику модели. Его задача — доставить сообщение до LLM и вернуть ответ.
4. **Гибкость** — пользователь может:
   - выбрать модель с нужным уровнем alignment,
   - использовать локальную модель без ограничений,
   - настроить системный промт персонажа.

## Что это значит для кода

- **Нет** чёрных списков слов.
- **Нет** модерационных функций.
- **Нет** проверок "можно/нельзя" перед отправкой в LLM.
- **Нет** фильтрации ответов LLM.
- **Нет** NSFW-классификаторов и сейфти-чеккеров.
- **Нет** принудительных инструкций в system prompt вида
  «ты не должна», «отказывайся от», «соблюдай политику».

## Как настроить контент

1. **Выберите LLM** — разные модели имеют разный alignment.
2. **Настройте системный промт персонажа** — в карточке персонажа
   (data/personas/characters/<name>/<name>.md) опишите характер, стиль речи,
   моральные принципы персонажа.
3. **Не добавляйте фильтры в код** — это нарушает архитектуру.

## Информационные поля

Поле nsfw: true/false в карточке персонажа — **только для информации**.
Код не принимает решений на основе этого поля.

## Для разработчиков

При добавлении нового кода:
- Не добавляйте проверки контента.
- Не фильтруйте ввод/вывод LLM.
- Не создавайте чёрные списки.
- Оставляйте контент-решения LLM.
- Если нужно передать модели контекст о контенте — используйте
  персонажа/системный промт, не код.

ответственность за соответствие законодательству своей страны.
